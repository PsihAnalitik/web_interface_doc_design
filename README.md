# AI Solution Copilot

Веб-интерфейс для уточнения технического задания: загрузка материалов, понимание проекта, таблица вопросов и копирование выбранных вопросов для обсуждения с заказчиком.

> Фронтенд подключён к Case Finder API: загрузка материалов, прогресс и два набора вопросов — по документам и с учётом похожих кейсов. Сервер сохраняет материалы и передаёт текст в OpenAI. Резюме и пояснения к вопросам текущий API не предоставляет. Кнопка «Посмотреть пример» работает отдельно без отправки материалов.

## Посмотреть интерфейс без запуска

PNG хранятся в репозитории и отображаются прямо в README на GitHub. Полная галерея: [все экраны интерфейса](docs/design/README.md) — загрузка, готовность, обработка, результаты, частичный результат, ошибка и мобильный вид.

## Структура

```text
.github/workflows/ci.yml       проверки и артефакт фронтенда
materials/                    исходные требования и материалы
docs/
  design/
    README.md                 галерея варианта
    copilot-mockups.html       исходный интерактивный прототип
    images/                   PNG интерфейса
  deployment.md               схема будущего развёртывания
web/
  dist/                       готовые HTML, CSS и JS; только это поставляется
  tests/                      проверки логики и тестовые документы
  package.json                команды запуска и проверок
  server.mjs                  сервер для локальной разработки
  README.md                   детали интерфейса и подключения анализа
case-finder-main/server/      FastAPI, worker и Docker Compose
```

`web/dist/` сейчас содержит редактируемые исходники статической страницы: сборщика нет, каталог **нужно хранить в Git**. Если появится сборщик, исходники можно перенести в `web/src/`, а `dist/` сделать генерируемым. Макеты, требования и PNG не относятся к публичным файлам приложения.

## Локальный запуск

Весь проект одной командой из корня репозитория. Нужны Bash, GNU Make,
Docker Engine и Docker Compose v2 с поддержкой `up --wait`.

Первичная настройка:

```bash
make init
# В case-finder-main/server/.env укажите OPENAI_API_KEY и API_USERS.
make up
```

После настройки для запуска достаточно `make up`. Откройте
http://127.0.0.1:4173 и введите логин/пароль из `API_USERS`.
API и worker используют зависимости из `uv.lock`; Python, uv и Node.js
на хосте для этого способа запуска не требуются.

```bash
make status     # состояние трёх сервисов
make logs       # логи; Ctrl+C прекращает просмотр, сервисы продолжают работать
make down       # остановить; данные заданий сохраняются
```

Другой порт интерфейса: `WEB_PORT=4174 make up`. Порт API задаёт `API_PORT`
в серверном `.env`. Используется тот же Compose-проект и volume, что и при
запуске из `case-finder-main/server`; `make down` не удаляет volume.
Собственная конфигурация: `make up ENV_FILE=/абсолютный/путь/.env`.
`make init` не перезаписывает существующую конфигурацию.

### Только фронтенд без Docker

Node.js 22 или новее; установка npm-зависимостей не требуется.

```sh
cd web
npm start
```

Открыть http://127.0.0.1:4173. Для анализа предварительно запустите API и worker
по [инструкции сервера](case-finder-main/server/README.md), затем введите в интерфейсе
логин и пароль из `API_USERS`. Веб-сервер ожидает API на `http://127.0.0.1:8000`;
другой адрес задаётся переменной `API_URL`. Без сервера доступен демопример.
[Подробности и проверки интеграции](web/README.md).

## Работа с GitHub

Один репозиторий для кода, требований и дизайна. Для этого размера проекта достаточно одной основной ветки и коротких рабочих веток `feature/<topic>` / `fix/<topic>` с pull request. Отдельные репозитории для макета и приложения не нужны.

Рекомендуемая основная ветка — `main`. Текущий локальный Git инициализирован с веткой `master`, коммитов пока нет; переименование, первый коммит и push выполняются при создании GitHub-репозитория. CI не привязан к имени ветки и будет работать с обоими вариантами.

После первого запуска CI настройте правило основной ветки: изменения через pull request и успешная проверка `Check frontend`. PNG интерфейса обновляйте вместе с изменениями интерфейса в том же PR. Для нескольких небольших PNG обычного Git достаточно; LFS сейчас не нужен.

## CI и дальнейший CD

На push и pull request GitHub Actions выполняет:

```sh
cd web
npm run check
npm test
```

После успешной проверки сохраняется артефакт `copilot-web-<commit SHA>` с содержимым `web/dist/`. Артефакт не содержит `materials/`, `docs/`, тестов и локального сервера.

Автодеплой пока не включён: сервер не выбран. [Схема CD и базового развёртывания](docs/deployment.md) описывает следующий шаг без привязки к поставщику сервера.
