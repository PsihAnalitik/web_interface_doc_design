## Задача

Разработать веб-интерфейс для загрузки документа, запуска его обработки Системой и получения обратной связи непосредственно на странице сайта.

Интерфейс должен поддерживать следующий цикл: **загрузка документа → обработка → просмотр результатов → исправление документа вне сайта → повторная загрузка и обработка**.

## Функциональные требования

### 1. Загрузка документа

- При заходе на сайт пользователь видит форму, в которую он может написать текстом или скопировать из буфера обмена текст описания задачи и/или может загрузить один или несколько файлов для анализа технического задания. 
- Пользователь может загрузить документы через диалог выбора файла или перетаскиванием в область загрузки.
- После загрузки отображаются название, формат и размер загруженный файлов.
- До запуска обработки пользователь может удалить или заменить любой загруженный файл.
- Если происходит ошибка загрузки документа, отображается понятное сообщение с причиной отказа.
- Если пользователь хочет проанализировать другой документ в интерфейсе есть кнопка, позволяющся проанализировать другое техническое задание - для этого открывается тот же интерфейс без введенных файлов в новом окне браузера.

### 2. Запуск и состояние анализа документа

- Анализ документов запускается кнопкой «Проанализировать техническое задание», доступной когда в поле ввода есть текст или когда был загружен один или несколько файлов.
- Интерфейс различает состояния: загрузка, готовность к обработке, обработка, завершение, частичный результат и ошибка.
- Во время обработки отображается индикатор выполнения.
- При сбое пользователь получает сообщение об ошибке и возможность повторить обработку.

### 3. Отображение результатов анализа

- По результатам анализа отображается краткая суммаризация (2-3 абзаца) с описанием системы которую нужно создать (исходя из данных технического задания).
- Под ней идут таблица с уточняющими вопросами (N = 20).
- Каждый уточняющий вопрос это блок:
  - кнопка выделения (like) - можно выделить лучшие вопросы
  - текст вопроса (крупным шрифтом);
  - подсистема - к какой части системы или окружения системы относится этот вопрос (мелким шрифтом)
  - текущее понимание - краткий абзац - что удалось понять из текущего ТЗ относительно этого вопроса (мелким шрифтом). Если в ТЗ никакой информации нет, то обозначить что информация отсутствует.  
  - обоснование важности - почему этот вопрос важный - как неопределенность может повлиять на сроки, стоимость или бизнес-успех реализации системы.
- Нужно чтобы при промотке (scroll down) на стандартный экран помещались все N вопросов, при этом шрифт (как вопросов, так и текущего понимания и обоснования важности) был читаемым.

### 4. Выбор и копирование вопросов

- Каждый вопрос можно независимо выбрать кнопкой like (задний фон у блока выделенного вопроса также слегка подсвечивается)
- Доступны действие «Снять выделение».
- Отображается количество выбранных вопросов.
- Кнопка «Копировать лучше вопросы в буфер обмена» копирует выбранные вопросы в буфер обмена в виде нумерованного списка, в порядке отображения (текст вопросов + текущее понимание).
- После копирования отображается подтверждение.
- Также рядом с кнопкой копирования в буфер появлется кнопка "Проанализировать другое ТЗ" которая откроет тот же интерфейс без загруженных файлов в новом окне (см. выше в пункте 1)

### 5. Логирование запросов

- Каждая обработка ТЗ логируется
- Для каждой попытки хранятся:
  - Загруженные пользователем файлы и текст который он ввел в форму ввода
  - Суммаризация проекта
  - Список вопросов, подсистема, текущее понимание, обоснование важности и статус выделения like для тех вопросов которые выделил пользователь

## Функциональные ограничения

- Поддерживаются только файлы форматов `.md`, `.docx`, `.pdf`, `.txt`.
- Максимальный размер одного файла — 30 МБ.
- Во время обработки нельзя запустить повторную обработку или заменить текущий документ (но можно "проанализировать другое ТЗ" и открыть тот же вебсайт на другой вкладке браузера.
- Пустые, повреждённые и недоступные для чтения документы не принимаются в обработку.
- Для PDF поддерживаются документы с доступным текстовым содержимым. Распознавание сканов и изображений не предусмотрено.
- Редактирование документа внутри интерфейса не предусмотрено.
- Копирование выбранных вопросов в буфер обмена недоступно, если ни один вопрос не выбран.
- История проверок, сравнение версий документов и чат для обсуждения результатов не входят в первую версию.

## Нефункциональные требования

- **Удобство использования:** основные действия имеют понятные подписи; сообщения об ошибках объясняют проблему и доступные дальнейшие действия.
- **Доступность:** основные действия доступны с клавиатуры. Важность замечаний и состояния обработки обозначаются не только цветом, но и текстом.
- **Адаптивность:** интерфейс пригоден для использования на компьютере и мобильном устройстве. Длинные замечания и вопросы доступны для чтения полностью.
- **Отзывчивость:** во время ожидания результата интерфейс остаётся отзывчивым и показывает текущее состояние обработки.
- **Сохранность частичного результата:** ошибка обработки не приводит к исчезновению уже полученных и доступных для отображения замечаний.
- **Конфиденциальность:** до загрузки пользователю доступны сведения о том что система работает в тестовом режиме и что не следует загружать конфиденциальные документы.
- **Безопасность:** загруженные документы и результаты обработки не должны приводить к выполнению посторонних действий или раскрытию данных других пользователей.
