# Домен: LLM-ассистенты и агентские системы

## Принадлежность компонента домену

Проверяй компонент, а не маркетинговое имя проекта.

- **Относится**, если в источнике LLM либо проектируемому языковому ассистенту поручены понимание/генерация текста, ответ по материалам, диалог, выбор следующего шага или вызов инструмента по запросу. Названная задача достаточна для принадлежности; отсутствие конкретной модели — неизвестная реализация.
- **Внешняя зависимость**, если компонент поставляет вход или исполняет вызов ассистента, но его собственная задача — распознать изображение, прогнозировать числовой ряд, обучить отдельную предиктивную модель или управлять физическим устройством. Извлекай его интерфейс, ограничения и явно описанные результаты; не объявляй достижимым его качество на основании опыта с LLM.
- **Недостаточно для классификации**, если сказано только «ИИ», «умная система» или «агент», без задачи и способа участия в процессе. Сохрани известное описание и неизвестную роль; не назначай RAG, обучение или автономные действия.
- **Не относится к текущему компоненту**, если операция явно выполняется только человеком или другой системой за его границей. Она может относиться к пользовательскому сценарию, интеграции или контролю: исключение из действий агента не исключает её из паспорта.

## Различия, меняющие проверку

| Условие в источнике | Что проверять | Что из него не следует |
|---|---|---|
| Агент создаёт текст для чтения/редактирования человеком | Вход, содержание результата, использование и исправление ответа | Нужны полномочия на отправку или транзакционный откат |
| Агент отправляет сообщение, меняет запись или вызывает внешний эффект | Конкретную операцию/объект, право, подтверждение и восстановление по последствиям | Любой вызов инструмента меняет состояние; чтение тоже может требовать права |
| Ответ строится с поиском в корпусе | Источник и версия корпуса, отбор материалов, права, актуальность; качество поиска отдельно от ответа | Наличие документов гарантирует покрытие; любая загрузка текста означает RAG |
| Назван инструмент/API | Доступную операцию, вход, результат, ошибки и ограничения интерфейса | Интерфейс существует в доступном контуре или разрешает запись |
| Задана локальная модель/ресурс | Условия исполнения, нужную длину входа, нагрузку и измерения на этом контуре | Размер модели доказывает качество; локальная модель исключает любые внешние вызовы |

Извлекай перечисленные атрибуты, только если они указаны. Не добавляй технологию, численные нормативы или новые функции вместо автора. Общая процедура принадлежности и неполноты — в methodology/evidence.md.

## Граница уровней проработанности

Эта таблица применяется синтезом к конкретному компоненту и заявленным условиям; это не шкала качества команды.

| Уровень | Достаточное основание для выбора | Недостаточное / иной уровень |
|---|---|---|
| repeat_deployment | Есть выполненное сопоставимое решение именно фиксированной команды; явно обосновано, какие существенные условия совпадают и что можно повторить | Стаж, название модели, чужой кейс или только план работ |
| known_approach | Назван метод/аналог, его результат и связь с задачей; существенные отличия перечислены, результат в новых условиях пока не подтверждён | Одно название технологии без результата и связи с задачей |
| experiment | Выбран конкретный ещё не подтверждённый вариант и проверяемое неизвестное; описано наблюдение, способное подтвердить/опровергнуть гипотезу | Само слово «пилот» или обещание «попробуем ИИ» |
| research | Источник явно устанавливает, что подход к обязательной задаче ещё требуется найти, и даёт основание: рассмотренные ограничения/неподходящие методы/открытую постановку | Отсутствует приложенное описание метода — это недостаток сведений, не доказательство отсутствия подхода |
| undetermined | Нет достаточного основания ни для одного из четырёх выводов либо основания об одном компоненте неразрешимо расходятся | Это не синоним невозможности или фундаментального исследования |

Если известный подход требует отдельного опыта по переносу, укажи known_approach для метода и непроверенное условие в reason; если отдельно оценивается именно опыт переноса, для него может быть experiment. Назови границу компонента, чтобы не присваивать два конкурирующих уровня одному и тому же выводу. Не превращай годы стажа, имена моделей и аналоги в сроки, стоимость или предложение расширить фиксированную команду.

## Граничные примеры — не данные проекта

| Вход | Решение и разделяющий признак |
|---|---|
| «Ассистент читает заявку и пишет черновик; отправляет оператор» | Генерация в домене, отправка вне действий агента: явно назван другой исполнитель |
| «Ассистент читает заявку и сам отправляет письмо после подтверждения» | Генерация и отправка в домене действий; подтверждение не переносит исполнение отправки на человека |
| «Инструмент возвращает остаток товара» | Чтение через инструмент; не приписывать резервирование товара без операции записи |
| «OCR превращает скан в текст, LLM проверяет текст договора» | OCR — внешний компонент; анализ текста в домене. Успех LLM не доказывает качество OCR |
| «Агент прогнозирует спрос» | Без описания модели/операции роль LLM неизвестна; слово «агент» не даёт границы домена |
| «На вход передаётся один полный регламент; поиска по корпусу нет» | Ответ по документу; не навязывать индекс, retrieval или оценку ранжирования |
| «Берём пять релевантных фрагментов из индекса и формируем ответ» | Заявлен поиск с последующей генерацией; проверить отбор и ответ отдельно |
| «Локальная LLM отправляет запросы к внешнему поиску» | Локальный инференс не равен изолированному контуру; учитывать внешний маршрут |
| «Наша команда уже внедрила такую же проверку на том же корпусе и контуре; различается только оформление» | repeat_deployment допустим при подтверждающих источниках и действительно ограниченном изменении |
| «Чужой документированный кейс показывает тот же метод на другом корпусе» | known_approach при обоснованной связи; не собственный опыт и не гарантия переноса |
| «Сравним два конкретных retrieval-варианта; гипотеза — rerank снижает долю пропусков на размеченных запросах» | experiment для проверки гипотезы; названо различающее наблюдение |
| «Описание реализации не передано» | undetermined; отсутствие документации не переводить в research |
| «Исследовательский агент использует повторно внедрённый нами поиск по статьям» | Имя агента не делает компонент research; проверять собственный аналог и условия |
| «Все рассмотренные методы нарушают обязательную анонимность; подход, удовлетворяющий ей, ещё нужно найти» | research при подтверждении постановки и рассмотренных ограничений; не факт невозможности решения |
