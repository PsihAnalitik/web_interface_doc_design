# Действия системы

## Назначение и граница цеха
Выделяй, что делает система: получает сведения, вычисляет, готовит предложение или изменяет внешнее состояние. Не выводи полномочия из слова «агент». Техническая доступность API и разрешение действия — разные основания.

Применяй общие правила источников, неполноты и статусов из [методологии свидетельств](../methodology/evidence.md). Раздел ниже активируется только для указанной проверки. Один фрагмент может относиться к нескольким проверкам: сохраняй смысл каждого пересечения.

## Извлечение по проверкам

### `agent_actions.operations`

**Относится, если:** Система явно названа исполнителем операции над объектом или производителем результата. Операция может только готовить предложение и не менять внешнее состояние. Явное отрицание выполнения также относится.

**Не относится:** Действие пользователя без участия системы; наличие метода API; намерение подключиться без конкретной операции. Чужие возможности не становятся полномочиями агента.

**Извлечь:** Исполнитель; операция; объект; источник чтения или место записи; получатель; черновик или выполненное действие; побочный эффект, если описан. Для SQL различай текст запроса и исполнение в БД; для сообщений — черновик и отправку.

**Если сведений не хватает:** «Обрабатывает заявку» — частичное found о заявленной операции с неизвестным содержанием; не подставляй изменение статуса. «Есть интеграция» без операции не подтверждает действия записи.

#### Синтетические граничные примеры — не данные проекта

1. **Вход:** «Агент читает справочник и готовит предложение исправления; запись делает редактор.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь чтение и подготовку; автоматическую запись исключить из действий агента. **Решающий признак:** Исполнитель изменения явно другой.

2. **Вход:** «Агент выдаёт текст SQL человеку, запрос в БД не исполняет.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь генерацию текста и отрицание выполнения; не приписывать доступ к БД. **Решающий признак:** Предложение команды не равно её исполнению.

3. **Вход:** «API поддерживает удаление записей.»
   **Решение:** Не относится к операции агента. **Извлечь / не выводить:** Не извлекать разрешённое удаление без связи с системой проекта. **Решающий признак:** Техническая возможность не является заявленным действием.

4. **Вход:** «Агент обрабатывает заявку.»
   **Решение:** Относится, частично. **Извлечь / не выводить:** Сохранить заявленную обработку; оставить чтение, изменение статуса и отправку неизвестными. **Решающий признак:** Объект назван, смысл операции не раскрыт.

5. **Вход:** «После подтверждения агент отправляет письмо адресату из заявки.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь отправку и адресата вместе с условием подтверждения; условие также относится к boundaries. **Решающий признак:** Есть внешний эффект с явным предусловием.


### `agent_actions.boundaries`

**Относится, если:** Фрагмент устанавливает, какую операцию система может или не может выполнить, при каком условии, над какими объектами и в каком объёме. Прямое указание, что полномочия не решены, также относится.

**Не относится:** Ограничение производительности без ограничения полномочий; доступность инфраструктуры; роль пользователя без связи с действием. Отсутствие запрета не устанавливает разрешение.

**Извлечь:** Действие и объект; разрешение/запрет; условие выполнения; предел количества или области; исключение; действие при несоблюдении условия, если оно указано. Условие подтверждения относится также к human_control, но не означает наличие описанного механизма подтверждения.

**Если сведений не хватает:** «Только безопасные действия» — частичное found о намерении ограничить действия, но без конкретной границы; не назначай свой список разрешённых операций.

#### Синтетические граничные примеры — не данные проекта

1. **Вход:** «Агент может менять только черновики своих заявок; опубликованные заявки доступны только для чтения.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь две области и разные полномочия; не расширять запись на чужие черновики. **Решающий признак:** Предел задан состоянием и принадлежностью объекта.

2. **Вход:** «Отправка разрешена только после подтверждения менеджером; иначе остаётся черновик.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь предусловие и ветку без подтверждения; не выдумывать кнопку или журнал согласия. **Решающий признак:** Дано разрешение с условием и альтернативой.

3. **Вход:** «В документации нет запрета удаления.»
   **Решение:** Не относится как разрешение удаления. **Извлечь / не выводить:** Сохранить отсутствие сведений при необходимости, не выдавать агенту право удаления. **Решающий признак:** Молчание не задаёт полномочие.

4. **Вход:** «Агент выполняет только безопасные операции.»
   **Решение:** Относится, частично. **Извлечь / не выводить:** Извлечь неопределённое ограничение; запросить разрешённые операции, не выбирать их самому. **Решающий признак:** Норматив назван, разделяющая граница не определена.

5. **Вход:** «Для пилота запись запрещена. В том же пилоте агент автоматически меняет статус заявки.»
   **Решение:** Относится. **Извлечь / не выводить:** Сохранить запрет и конфликтующую операцию; не считать смену статуса чтением. **Решающий признак:** Одна и та же область одновременно запрещает и требует изменение состояния.

## Заключение по проверкам
operations оценивай по определённости действий и объектов; boundaries — по границам, необходимым для этих действий. Не требуй отмены внешних изменений, если они прямо исключены. При явно запрещённой записи частная проверка её условий может быть not_applicable, но чтение и генерация остаются операциями. Неизвестные полномочия — insufficient_data; явная операция, запрещённая в той же области, — not_satisfied.

Ни один пример не дополняет исходный документ фактами. Решения «относится / не относится / неопределённо» описывают отбор свидетельств, а не новые значения статусов выходной схемы.
