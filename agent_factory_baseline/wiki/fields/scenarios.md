# Пользовательские сценарии и границы

## Назначение и граница цеха
Описывай пользовательское взаимодействие и границы текущей версии. Различай требование, пример, демонстрацию и будущую идею. Задачи за пределами LLM-ассистентов и агентских систем отмечай как внешние зависимости без оценки их сложности.

Применяй общие правила источников, неполноты и статусов из [методологии свидетельств](../methodology/evidence.md). Раздел ниже активируется только для указанной проверки. Один фрагмент может относиться к нескольким проверкам: сохраняй смысл каждого пересечения.

## Извлечение по проверкам

### `scenarios.flow`

**Относится, если:** Фрагмент описывает действие участника по отношению к системе или передачу ему результата в сценарии анализируемого продукта. Даже отдельный переход относится, если привязка к продукту установлена.

**Не относится:** Внутренний алгоритм без пользовательского перехода; общая способность платформы; история стороннего продукта без связи с текущим сценарием.

**Извлечь:** Триггер; роль; подаваемый вход; действие пользователя и реакция системы; условие ветвления, уточнение или передача человеку; получаемый результат; текущая версия, будущая идея или иллюстрация. Не дописывай экран, загрузку и обработку ошибок по одному вопросу.

**Если сведений не хватает:** Один переход — частичное found, а не полный сценарий. При неясной принадлежности примера текущему продукту сохрани статус неопределённым; не превращай его в обязательство.

#### Синтетические граничные примеры — не данные проекта

1. **Вход:** «В Baseline студент загружает Markdown и получает список вопросов к документу.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь роль, вход и выход, область Baseline. **Решающий признак:** Взаимодействие относится к текущей версии.

2. **Вход:** «Если в документе нет контекста, агент просит автора указать цель и ждёт ответа.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь условную ветку и ожидание; не обещать ответ без уточнения. **Решающий признак:** Есть различимый альтернативный переход.

3. **Вход:** «Модель разбивает текст на токены.»
   **Решение:** Не относится. **Извлечь / не выводить:** Не выводить пользовательский поток из внутренней операции. **Решающий признак:** Нет взаимодействия участника с продуктом.

4. **Вход:** «Например, другой агент бронирует переговорную через календарь.»
   **Решение:** Не относится к сценарию текущего продукта. **Извлечь / не выводить:** Не требовать календарь или бронирование. **Решающий признак:** Пример прямо отнесён к чужому продукту.

5. **Вход:** «Пример: пользователь пишет «проверь договор». Принадлежность примера продукту не пояснена.»
   **Решение:** Неопределённо. **Извлечь / не выводить:** Сохранить пример и неопределённость; не дописывать загрузку договора, юридическую проверку и обязательный scope. **Решающий признак:** Пример не связан однозначно с обязательствами продукта.


### `scenarios.scope`

**Относится, если:** Фрагмент устанавливает, включён ли сценарий/компонент, запрещён ли, отложен ли, обязателен или желателен, и для какой версии/условий. Явная неопределённость статуса тоже относится.

**Не относится:** Общая возможность библиотеки, подробный пример без статуса требования, техническая сложность сама по себе. Молчание о сценарии не задаёт его границу.

**Извлечь:** Сценарий или компонент; включение/исключение; обязательность; версия или этап; условие, при котором граница меняется; внешняя зависимость. Не превращай «позже» в отсутствие навсегда и «можно» в обязательно.

**Если сведений не хватает:** «Экспорт обсуждается» — found с нерешённой границей. Если вход не определяет принадлежность примера продукту, не выбирай включение по подробности описания.

#### Синтетические граничные примеры — не данные проекта

1. **Вход:** «В Baseline только разовая проверка документа; диалог запланирован после пилота.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь включённую проверку и отложенный диалог с этапами. **Решающий признак:** Один сценарий исключён лишь из текущей версии.

2. **Вход:** «Экспорт CSV желателен, при его отсутствии пилот всё равно запускаем.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь желательность и отсутствие блокировки пилота, не обязательность. **Решающий признак:** Приоритет установлен явным последствием отсутствия функции.

3. **Вход:** «Платформа умеет работать с календарями.»
   **Решение:** Не относится. **Извлечь / не выводить:** Не объявлять календарь включённым в проект. **Решающий признак:** Способность средства не задаёт объём продукта.

4. **Вход:** «Экспорт договора обсуждается; решение о первой версии не принято.»
   **Решение:** Относится, частично. **Извлечь / не выводить:** Извлечь нерешённый статус, не включение и не исключение. **Решающий признак:** Неопределённость scope прямо заявлена.

5. **Вход:** «В требованиях пилота экспорт обязателен; в антицелях того же пилота экспорт запрещён.»
   **Решение:** Относится. **Извлечь / не выводить:** Сохранить конфликт одной версии; не снимать его ссылкой на разные разделы. **Решающий признак:** Нет условия, разделяющего несовместимые границы.

## Заключение по проверкам
flow проверяй по различимости заявленных взаимодействий, scope — по определённости их версии и обязательности. Явно исключённый частный сценарий может быть not_applicable для его детализации; это не отменяет проверку границ. Будущая идея не блокирует текущий эксперимент без указанной зависимости. Конфликт обязательности и запрета в одной области — not_satisfied; неясный статус — insufficient_data.

Ни один пример не дополняет исходный документ фактами. Решения «относится / не относится / неопределённо» описывают отбор свидетельств, а не новые значения статусов выходной схемы.
