# Ожидаемое изменение

## Назначение и граница цеха
Выделяй желаемое изменение в работе человека или бизнеса и способ заметить его достижение. Функция системы является средством, пока не описан изменяемый результат процесса. Не добавляй обязательную монетизацию.

Применяй общие правила источников, неполноты и статусов из [методологии свидетельств](../methodology/evidence.md). Раздел ниже активируется только для указанной проверки. Один фрагмент может относиться к нескольким проверкам: сохраняй смысл каждого пересечения.

## Извлечение по проверкам

### `expected_outcome.result`

**Относится, если:** Фрагмент задаёт желаемую новую возможность участника либо изменение результата, усилий, времени, ошибок или способа работы процесса. Нужна связь с участником/процессом, но не обязательно численная цель.

**Не относится:** Название модели, БД, число агентов, сам факт генерации без пользовательского результата. Текущее затруднение без заявленного изменения относится к business_problem.

**Извлечь:** Получатель изменения; действие или результат процесса; направление изменения; границы эффекта; обязательство, ориентир или гипотеза; срок, если дан. Не превращай помощь человеку в автономное решение и первый ответ в полный цикл.

**Если сведений не хватает:** «Ускорить проверку» — частичное found с известным направлением и неизвестной величиной; отсутствие порога не отменяет смысла результата. «Сделать лучше» без объекта — неопределённый эффект.

#### Синтетические граничные примеры — не данные проекта

1. **Вход:** «Методист получает замечания до встречи и тратит встречу на обсуждение спорных условий.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь изменение подготовки и использования встречи; не выводить уменьшение общей длительности. **Решающий признак:** Описан способ работы получателя.

2. **Вход:** «Хотим сократить время подготовки замечаний.»
   **Решение:** Относится, частично. **Извлечь / не выводить:** Извлечь направление изменения, не придумывать целевое число. **Решающий признак:** Результат задан без измерительного порога.

3. **Вход:** «Используем векторную БД и три агента.»
   **Решение:** Не относится. **Извлечь / не выводить:** Не выводить полезность архитектуры для пользователя. **Решающий признак:** Перечислены средства без изменения процесса.

4. **Вход:** «Агент выдаёт JSON.»
   **Решение:** Не относится без связи с результатом пользователя. **Извлечь / не выводить:** Отнести формат к сценарию или действию; не обещать автоматизацию труда. **Решающий признак:** Формат выхода сам по себе не описывает полезное изменение.

5. **Вход:** «Ожидаем, что подсказки помогут студентам самим находить пропуски; готовые решения агент не выдаёт.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь гипотезу самостоятельного выявления пропусков и ограничение помощи. **Решающий признак:** Пользовательский эффект может быть педагогическим и качественным.


### `expected_outcome.success`

**Относится, если:** Назван показатель, наблюдаемое поведение, оценочная процедура или правило сравнения, явно используемое для проверки заявленного эффекта. Не обязательно решение о выпуске продукта: оно отдельно относится к acceptance.

**Не относится:** Не связанная с эффектом техническая метрика, неопределённое «успешно» без признака и статистика чужого проекта как якобы достигнутая цель текущего. Наличие теста ещё не доказывает полезность.

**Извлечь:** Какой эффект проверяется; показатель или наблюдаемый качественный признак; исходное и целевое значения раздельно; объект сравнения; срок и условия; кто наблюдает, если дан; обязательный порог, ориентир или гипотеза. Для относительной цели не вычисляй неизвестную базу.

**Если сведений не хватает:** Показатель без порога — found; достаточность зависит от решения: описательное сравнение может не требовать победителя, приёмка требует своего правила. «Полезность» без определения — частичное свидетельство намерения оценивать, не готовый измеритель.

#### Синтетические граничные примеры — не данные проекта

1. **Вход:** «Успех — студент на повторной попытке самостоятельно устраняет указанный пропуск; это отмечает методист.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь наблюдаемое действие и оценщика; не требовать денежной метрики. **Решающий признак:** Качественный признак проверяем через описанное действие.

2. **Вход:** «Цель — сократить время подготовки на 20%; исходное время ещё не замерено.»
   **Решение:** Относится, частично. **Извлечь / не выводить:** Извлечь относительную цель и неизвестную базу; не придумывать минуты. **Решающий признак:** Цель задана, основание сравнения неполно.

3. **Вход:** «Сравним число вопросов, признанных экспертами полезными, в двух вариантах; пока только отчёт без выбора победителя.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь показатель и описательное сравнение; не требовать порог допуска в продукт. **Решающий признак:** Исследовательский результат не обязательно является приёмкой.

4. **Вход:** «GPU загружен на 90%; цель проекта — самостоятельная работа студента. Связь не описана.»
   **Решение:** Не относится к успеху этого эффекта. **Извлечь / не выводить:** Сохранить техническое измерение в соответствующем контексте; не приравнивать загрузку к обучению. **Решающий признак:** Метрика не проверяет заявленное изменение.

5. **Вход:** «Будем оценивать полезность обратной связи. Как понимать полезность, ещё не согласовано.»
   **Решение:** Относится, частично. **Извлечь / не выводить:** Извлечь намерение и несогласованное определение; verdict insufficient_data для проверки достижения эффекта. **Решающий признак:** Есть предмет оценки, но нет разделяющего признака успеха.

## Заключение по проверкам
result оценивай по определённости изменения для участника/процесса; success — по возможности проверить именно это изменение в заявленной задаче. Не переноси неполноту success автоматически в result. Недостающая процедура или значение, необходимое заявленному решению, — insufficient_data. Несовместимые обязательные результаты в одной области — not_satisfied. Исключённый финансовый эффект не возвращай как обязательный.

Ни один пример не дополняет исходный документ фактами. Решения «относится / не относится / неопределённо» описывают отбор свидетельств, а не новые значения статусов выходной схемы.
