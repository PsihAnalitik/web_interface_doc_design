# Текущий процесс

## Назначение и граница цеха
Восстанавливай фактический порядок до изменения и его исходные характеристики. Не проектируй будущий workflow. Явно новый процесс может не иметь предшественника; это допустимая граница, а не повод выдумать ручную историю.

Применяй общие правила источников, неполноты и статусов из [методологии свидетельств](../methodology/evidence.md). Раздел ниже активируется только для указанной проверки. Один фрагмент может относиться к нескольким проверкам: сохраняй смысл каждого пересечения.

## Извлечение по проверкам

### `current_process.steps`

**Относится, если:** Фрагмент описывает действие или переход в существующем до внедрения процессе либо прямо говорит, что такого процесса ещё нет. Время устанавливай по контексту, а не только по форме глагола.

**Не относится:** Проектируемые действия агента, будущий интерфейс, целевая схема без описания исходного процесса. Ссылка на недоступный регламент не раскрывает его шаги.

**Извлечь:** Событие начала; исполнитель; действие и объект; инструмент; порядок или условия перехода; проверка, возврат и передача результата. Извлекай только названные шаги, не заполняя пробелы отраслевым стандартом.

**Если сведений не хватает:** Один известный шаг — found с неполной цепочкой. Если из текста нельзя определить, текущий это процесс или план, сохрани неопределённость времени; не выбирай настоящее по умолчанию.

#### Синтетические граничные примеры — не данные проекта

1. **Вход:** «Сейчас эксперт читает документ, записывает замечания и отправляет их автору.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь три действия, участников и передачу; не придумывать согласование руководителем. **Решающий признак:** Явно обозначен текущий порядок.

2. **Вход:** «Сегодня замечания передаёт секретарь; как они составляются, не описано.»
   **Решение:** Относится, частично. **Извлечь / не выводить:** Извлечь известную передачу и оставить подготовку неизвестной. **Решающий признак:** Неполная цепочка содержит действительный шаг.

3. **Вход:** «Агент будет читать документ и сам создавать задачу в трекере.»
   **Решение:** Не относится. **Извлечь / не выводить:** Отнести к будущему сценарию и действиям системы. **Решающий признак:** Будущее действие не является baseline.

4. **Вход:** «Документ проверяется и отправляется руководителю. Контекст времени отсутствует.»
   **Решение:** Неопределённо. **Извлечь / не выводить:** Сохранить фрагмент с неизвестным временным статусом; не утверждать, что это текущая практика. **Решающий признак:** Нет признака до или после внедрения.

5. **Вход:** «Это новый сервис; до проекта такую проверку никто не проводил.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь явное отсутствие предшественника; не создавать ручные шаги. **Решающий признак:** Отсутствие процесса прямо заявлено.


### `current_process.baseline`

**Относится, если:** Утверждение характеризует состояние процесса до изменения: затраты времени, объём, ошибки, ожидания, ручной труд, ограничения или субъективную оценку участника. Также относится прямое указание, что исходное измерение неизвестно.

**Не относится:** Целевые показатели будущего продукта, скорость чужого решения и запланированное измерение, выдаваемое за уже выполненное. План сбора baseline извлекай только как план, если он явно относится к этой проверке.

**Извлечь:** Характеристика и её значение; процесс и участник; измерение или оценка; единица, период, знаменатель и условия. Для времени сохраняй различие активной работы, ожидания и полного цикла, только если оно установлено. Отдельно сохраняй дату будущего замера без результата.

**Если сведений не хватает:** «Долго» — found о субъективной оценке, но не число и не сопоставимая величина. Неясные единицы или границы замера оставляй неизвестными.

#### Синтетические граничные примеры — не данные проекта

1. **Вход:** «В июне эксперт тратил на чтение в среднем 40 минут; ожидание согласования в замер не входило.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь 40 минут, июнь, среднее активного чтения, исключённое ожидание. **Решающий признак:** Определена граница исходного замера.

2. **Вход:** «Эксперты называют нынешнюю проверку долгой.»
   **Решение:** Относится, частично. **Извлечь / не выводить:** Извлечь субъективную оценку текущего процесса, не среднюю длительность. **Решающий признак:** Качественная характеристика релевантна без числа.

3. **Вход:** «После запуска проверка должна занимать не более двух минут.»
   **Решение:** Не относится. **Извлечь / не выводить:** Извлечь целевой показатель в expected_outcome или service_requirements, не в измеренный baseline. **Решающий признак:** Норматив будущего не описывает настоящее.

4. **Вход:** «В следующем месяце измерим исходное время; сейчас оно неизвестно.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь неизвестность и план измерения; не записывать дату как выполненный замер. **Решающий признак:** План привязан к baseline, но результат отсутствует.

5. **Вход:** «Проверка занимает 30 минут. Неясно, включено ли ожидание.»
   **Решение:** Относится, частично. **Извлечь / не выводить:** Сохранить 30 минут и неизвестную границу; не сравнивать напрямую с временем работы модели. **Решающий признак:** Число есть, сопоставимость не установлена.

## Заключение по проверкам
steps: satisfied, если существенные для заявленного изменения шаги определены либо отсутствие предшественника явно объяснено. baseline: оценивай достаточность исходных характеристик для заявленного сравнения; не требуй числа, когда решение его не использует. Для относительного численного эффекта неизвестная база — insufficient_data. Одновременное наличие и отсутствие обязательного шага в том же контуре — not_satisfied. У явно нового процесса конкретный исторический baseline может быть not_applicable.

Ни один пример не дополняет исходный документ фактами. Решения «относится / не относится / неопределённо» описывают отбор свидетельств, а не новые значения статусов выходной схемы.
