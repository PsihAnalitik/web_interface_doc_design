# Пользователи и участники

## Назначение и граница цеха
Различай роли в пользовательском процессе и полномочия принимать решения. Это описание участников, а не предложение расширить фиксированную команду разработки. Один человек может совмещать роли только по источнику.

Применяй общие правила источников, неполноты и статусов из [методологии свидетельств](../methodology/evidence.md). Раздел ниже активируется только для указанной проверки. Один фрагмент может относиться к нескольким проверкам: сохраняй смысл каждого пересечения.

## Извлечение по проверкам

### `users.roles`

**Относится, если:** Роль или группа связана с конкретным взаимодействием с системой, передачей входа, получением выхода либо действием в затрагиваемом процессе; также относится явно названная роль заказчика данного проекта. Прямой доступ к интерфейсу не обязателен.

**Не относится:** Перечень разработчиков, подпись автора документа или название организации без установленной связи с продуктом. Чужие роли из иллюстративного кейса не становятся ролями текущего продукта.

**Извлечь:** Обозначение роли; действие или получаемый результат; прямое или опосредованное взаимодействие; явно названные различия между группами и условия доступа. Сохранить запланированную роль как запланированную; не требовать ФИО.

**Если сведений не хватает:** Роль без полного сценария остаётся found, если её действие определено. Слово «пользователь» без действия не позволяет восстановить обязанности; названную группу не дополняй правами.

#### Синтетические граничные примеры — не данные проекта

1. **Вход:** «Аналитик загружает документ и читает замечания агента.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь аналитика, загрузку и чтение замечаний. **Решающий признак:** Роль связана с действиями.

2. **Вход:** «Клиент получает подготовленный отчёт по почте от менеджера и не входит в сервис.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь клиента как получателя, менеджера как передающего результат; не давать клиенту доступ к сервису. **Решающий признак:** Опосредованный получатель тоже участник.

3. **Вход:** «В команде разработки есть ML-инженер.»
   **Решение:** Не относится без связи с процессом. **Извлечь / не выводить:** Извлечь в team_capabilities; не называть инженера конечным пользователем. **Решающий признак:** Разработка продукта не означает его использование в целевом процессе.

4. **Вход:** «Заказчик проекта — ИТ-директор.»
   **Решение:** Относится, частично. **Извлечь / не выводить:** Сохранить роль заказчика; не выводить ежедневную работу в интерфейсе или право приёмки. **Решающий признак:** Участие названо, конкретные пользовательские действия не названы.

5. **Вход:** «Пользователь нажимает кнопку проверки; кто именно будет пользователем, ещё не выбрано.»
   **Решение:** Относится, частично. **Извлечь / не выводить:** Извлечь действие и неопределённую группу; не подставлять аналитика. **Решающий признак:** Сценарная роль есть, носитель роли неизвестен.


### `users.ownership`

**Относится, если:** Участнику явно поручено владеть процессом, утверждать требования, принимать или отклонять результат, разрешать спор либо отвечать за содержание и исправление знаний. Указание, что ответственный не назначен, также относится.

**Не относится:** Простое участие в тестировании, пользование результатом, владение должностью или доступом к данным без ответственности за решение. Экспертная оценка и окончательное утверждение не тождественны.

**Извлечь:** Роль; конкретное решение или объект ответственности; предел полномочий; действует назначение или только планируется; порядок разрешения разногласий, если назван. Различай владельца процесса, владельца данных и принимающего результат, не объединяя их по умолчанию.

**Если сведений не хватает:** «Согласует заказчик» — found с ролью без ФИО. «Ответственный будет назначен» — found о незавершённом назначении, а не доказательство действующих полномочий.

#### Синтетические граничные примеры — не данные проекта

1. **Вход:** «Руководитель обучения утверждает правила критики, методист исправляет чек-лист.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь две роли и разные объекты ответственности. **Решающий признак:** Есть явное распределение решений.

2. **Вход:** «Результат принимает заказчик; имя представителя определим позже.»
   **Решение:** Относится, частично. **Извлечь / не выводить:** Извлечь полномочие роли заказчика и отложенное имя; не объявлять роль отсутствующей. **Решающий признак:** ФИО не требуется для наличия назначенной роли.

3. **Вход:** «Два эксперта размечают ответы модели.»
   **Решение:** Не относится к праву приёмки без другого контекста. **Извлечь / не выводить:** Сохранить в users.roles; не назначать экспертам право выпуска. **Решающий признак:** Выполнение оценки не устанавливает власть над решением.

4. **Вход:** «Владелец процесса пока не назначен.»
   **Решение:** Относится. **Извлечь / не выводить:** Извлечь прямое указание, что владелец пока не назначен; не подменять его отсутствием сведений. Статус зависит от обязательности назначения на текущем этапе. **Решающий признак:** Отрицательный факт об установленном предмете релевантен; «не назначен» отличается от «неизвестно, назначен ли».

5. **Вход:** «Только методист разрешает выпуск. Только руководитель разрешает выпуск; правила их согласования нет.»
   **Решение:** Относится. **Извлечь / не выводить:** Сохранить оба исключительных полномочия в одном контуре и конфликт, не выбирать старшую должность. **Решающий признак:** Несовместимые назначения не разрешаются организационным предположением.

## Заключение по проверкам
roles оценивай по возможности связать участников с действиями заявленного сценария; ownership — по определённости полномочий на нужные решения. Неизвестное назначение означает недостаток данных, а не отсутствие людей в организации. Конфликт исключительных полномочий в одном решении — not_satisfied. Исключённая дополнительная роль может быть not_applicable, но не делает неприменимым весь состав участников.

Ни один пример не дополняет исходный документ фактами. Решения «относится / не относится / неопределённо» описывают отбор свидетельств, а не новые значения статусов выходной схемы.
