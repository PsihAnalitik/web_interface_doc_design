# Источники данных

## Назначение и граница цеха
Составь перечень информации, необходимой ассистенту, и условий её получения. Различай пользовательские входы, справочные знания, внешние сервисы и данные для оценки. Источник может существовать, но ещё не быть предоставлен команде. Техническая ссылка на него не доказывает ни доступ, ни полноту содержимого.

## Извлечение по чек-листу
- `data_sources.inventory`: найди название источника, назначение в сценарии, владельца и состояние доступности. Отдели полученный файл от обещанной выгрузки и гипотетического подключения. Для wiki различай действующий материал, план наполнения и иллюстративный пример.
- `data_sources.updates`: найди структуру, объём, единицы измерения, частоту обновления и путь подготовки входов. Для Markdown сохрани предупреждения об утерянных таблицах, формулах, изображениях или вкладках. Если исходный PDF не прочитан, не описывай его содержимое по одному имени файла.

Ссылки на источники извлекай с ближайшим описанием их роли. Один и тот же файл может использоваться в нескольких целях, но обучающий пример не становится проверочной выборкой автоматически. Текущая фабрика анализирует Markdown; процесс преобразования других форматов находится вне её предметного анализа.

## Заключение
`satisfied`: названы существенные источники и известны условия их использования для сценария. `not_satisfied`: источник явно не содержит требуемый тип информации либо заявленные условия поставки противоречат обязательному обновлению. `insufficient_data`: неизвестно, что будет предоставлено или какая часть материала потеряна. `not_applicable`: конкретный внешний источник явно исключён; это не отменяет проверки основного пользовательского входа.

## Ложные срабатывания и вопросы
Число показателей в опыте команды не определяет объём данных нового продукта. Публичная документация API не подтверждает наличие клиентской выгрузки. Спроси: «Какой материал уже доступен для первого сравнения?» и «Какие части исходника не попали в Markdown и влияют ли они на проверяемый раздел?» Не требуй идеальной базы знаний, когда для эксперимента явно выбран ограниченный набор.

## Синтетические примеры — не данные проекта
Положительный: «Переданы пять Markdown-документов; изображения не переносились, список пропусков приложен». Наличие данных и ограничение полноты фиксируются отдельно.
Отрицательный: «После согласования дадим выгрузку». Это обещание предоставления, а не доказательство уже доступного источника.
