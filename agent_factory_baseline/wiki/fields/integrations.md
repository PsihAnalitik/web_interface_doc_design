# Интерфейсы интеграций

## Назначение и граница цеха
Установи, какие внешние интерфейсы нужны для конкретных действий и что известно об их применимости. Отделяй существование системы от наличия подходящего интерфейса. Не объявляй интеграцию невозможной из-за отсутствия документации в текущем пакете и не предполагай поддержку операций по названию продукта.

## Извлечение по чек-листу
- `integrations.interfaces`: найди систему, доступный протокол или API, используемые операции и ссылку на описание контракта. Для LLM-провайдера сохраняй существенные ограничения модели, формата ответа и параметров, только если они указаны. Для поиска отличай поисковый движок от непосредственного доступа к найденной странице.
- `integrations.conditions`: найди аутентификацию, доступ к тестовому контуру, лимиты, обработку отказов и ограничения окружения. Если повторный вызов меняет состояние, сохрани правила повторения и предотвращения дубликатов, когда они описаны. Не придумывай конкретный retry-план.

Ссылку на API без содержимого можно считать указанием на документацию, но нельзя выводить из неё неподтверждённые методы. Свяжи интерфейс с действием: чтение знаний и публикация ответа могут требовать разных полномочий и каналов.

## Заключение
`satisfied`: есть основания считать интерфейс соответствующим нужной операции и понятны существенные условия подключения. `not_satisfied`: описанный интерфейс явно не поддерживает обязательную операцию или его условия прямо несовместимы с заданным контуром. `insufficient_data`: метод, тестовый доступ или важное ограничение неизвестны. `not_applicable`: внешняя интеграция явно отсутствует в выбранном варианте; использование локальных файлов само по себе не требует сетевого API.

## Ложные срабатывания и вопросы
Упоминание стороннего кейса не создаёт обязательную интеграцию в текущем проекте. Совместимость с OpenAI-форматом не доказывает идентичность всех параметров провайдеров. Спроси: «Какой интерфейс предоставляет нужную операцию?» и «На каком контуре проверим ограничения подключения?» Не преобразуй эти вопросы в оценку сроков разработки адаптера или потребность нанять специалиста.

## Синтетические примеры — не данные проекта
Положительный: «Каталог доступен через read-only API; схема ответа и тестовый токен предоставлены». Для чтения есть конкретное основание интеграции.
Отрицательный: «В похожем проекте использовалась CRM». Без требования текущего сценария это не основание запрашивать CRM API или оценивать его доступность.
