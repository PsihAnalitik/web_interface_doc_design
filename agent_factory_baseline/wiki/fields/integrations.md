# Интерфейсы интеграций

## Назначение и граница цеха
Предмет — технический обмен агента с другой системой для указанного действия. Перечень данных описывает `data_sources`, полномочия — `access_rights`, среду исполнения — `deployment`. Интерфейс может быть локальным: наличие сети не является обязательным признаком интеграции. Если другая система поставляет файл агенту по заданному контракту обмена, это интеграция; ручное помещение пользовательского файла во входную папку само по себе отдельной межсистемной интеграцией не является.

Все примеры синтетические — не данные проекта.

## Извлечение по чек-листу

### `integrations.interfaces`
**Относится, если:** указан обмен с внешней для агента системой/компонентом для текущего или явно планируемого действия: запрос, получение, передача или изменение данных. Обмен может идти через API, очередь или файловую поставку другой системой. Достаточно заявленной потребности в интерфейсе, даже если метод неизвестен. Явное отсутствие подходящей операции также относится.

**Не относится:** название продукта в опыте команды; список материалов без обмена с системой; произвольная интеграция, придуманная из пользовательской роли. Локальный файл сам по себе не требует сетевого API. Название сервиса не доказывает поддержку нужной операции.

**Извлечь:**
- систему и действие, для которого требуется обмен;
- протокол/канал и метод/операцию, если названы;
- тип входа и ответа, существенные ограничения контракта;
- ссылку на описание и то, предоставлено ли его содержание;
- состояние: действует, проверяется, планируется, не определён или явно не поддерживается.

**Если сведений не хватает:** потребность «получить X из системы Y» сохраняй как `found`, но не изобретай API. Ссылка без прочитанной документации подтверждает только наличие ссылки. Если связь упомянутой системы с текущим действием неясна, сохраняй контекст как неоднозначный, не объявляй интеграцию обязательной.

#### Граничные примеры — синтетические
1. Вход: «Для поиска товаров используем read-only API каталога; метод поиска и схема ответа приложены». **Относится.** Извлечь систему, чтение, поиск и указание на контракт. Не выводить поддержку записи из существования API.
2. Вход: «Агент должен получать статус из CRM; способ получения ещё выбирается». **Относится, сведения частичные.** Извлечь обязательный обмен и неизвестный способ. Не утверждать, что API отсутствует или что нужен именно REST.
3. Вход: «В предыдущем проекте команда внедряла CRM». **Не относится.** Это опыт команды, а не требование подключать CRM в текущем сценарии.
4. Вход: «Для теста документы вручную кладут в локальную папку; иных систем в тесте нет». **Не относится как внешняя интеграция.** Извлечь вход в `data_sources`; не требовать сетевой endpoint загрузки для этого теста.
5. Вход: «Учётная система каждый вечер выгружает CSV в общую папку; агент принимает колонки ID и status по согласованной схеме». **Относится.** Извлечь систему, файловый канал, направление и контракт колонок. Отсутствие сетевого API не исключает межсистемный обмен.
6. Вход: «В пилоте агент обязан менять статус заказа; предоставленный интерфейс позволяет только читать заказ, других каналов нет». **Относится, явное несоответствие.** Извлечь требуемую запись и ограничение интерфейса. Отсутствие поддержки здесь прямо заявлено, а не угадано из отсутствия документации.

### `integrations.conditions`
**Относится, если:** условие влияет на возможность или корректность технического вызова определённого интерфейса: аутентификация, сетевой маршрут, тестовый доступ, квота, лимит, формат ошибки, тайм-аут, повтор или предотвращение дубликатов. План проверки этих условий относится как план.

**Не относится:** юридическое согласие само по себе; средняя задержка всего продукта без привязки к интерфейсу; численность разработчиков; наличие документации без утверждений об условиях подключения. Рабочий токен не доказывает право обрабатывать любые данные.

**Извлечь:**
- интерфейс, окружение и способ аутентификации без копирования секретного значения;
- наличие/обещание/отсутствие тестового доступа и проверенные условия соединения;
- значения лимитов с единицами, областью и периодом, если они указаны;
- виды ошибок, правила тайм-аутов, повторов и защиты от повторного изменения;
- ограничения формата/параметров и источник утверждения об их поддержке.

**Если сведений не хватает:** одно известное условие сохраняй как `found`; остальные не достраивай типичным retry-планом. Для меняющего состояние вызова не считай повтор безопасным без указанных оснований. Обязательность уточнения зависит от заявленного действия, а не от полного универсального перечня API-вопросов.

#### Граничные примеры — синтетические
1. Вход: «В тестовом API доступно 30 запросов в минуту на аккаунт; при 429 учитываем Retry-After». **Относится.** Извлечь квоту, область и обработку ошибки. Не переносить квоту теста на production без сведений о нём.
2. Вход: «Тестовый токен обещали после согласования». **Относится как условие будущего подключения.** Извлечь обещание и зависимость; не считать стенд проверенным или доступ уже полученным.
3. Вход: «Автор согласен на обработку своей работы». **Не относится как техническое подключение.** Это `access_rights.handling`; согласие не задаёт аутентификацию или доступность endpoint.
4. Вход: «Создание заявки повторяется после тайм-аута; механизм защиты от дублей не описан». **Относится, сведения частичные.** Извлечь повтор меняющего состояние вызова и неизвестную защиту. Не утверждать, что дубликаты уже возникли или что API идемпотентен.
5. Вход: «Провайдер объявлен совместимым с форматом OpenAI; поддержка используемого параметра strict не проверялась». **Относится.** Извлечь заявление о совместимости и непроверенный параметр. Не приравнивать совместимость формата к поддержке всех возможностей.

## Заключение
`satisfied` — есть основания соответствия интерфейса нужной операции и определены существенные условия подключения в заявленном этапе. `not_satisfied` — явно указанное свойство интерфейса или подключения несовместимо с обязательным действием. `insufficient_data` — существенная операция, условие или применимость неизвестны. `not_applicable` — внешние интеграции явно исключены из оцениваемого варианта; не переносить это на будущую версию с подключениями. Не превращать неизвестность API в оценку сроков адаптера или найма.
