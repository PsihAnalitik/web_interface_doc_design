# AI Solution Copilot — веб-интерфейс

Реализация варианта из [прототипа](../docs/design/copilot-mockups.html): адаптивная таблица, выбор отдельных вопросов и «Выделить все вопросы». [PNG интерфейса без запуска приложения](../docs/design/README.md).

## Запуск

Требуется Node.js 22 или новее. Зависимостей для установки нет.

```sh
cd web
npm start
```

Откройте http://127.0.0.1:4173. Другой порт: `PORT=4174 npm start`.

```sh
npm run check
npm test
```

Каталог `dist/` содержит готовую статическую страницу без этапа сборки. Его можно обслуживать любым HTTP-сервером. Открытие через `file://` не поддерживается из-за ES modules.

## Что реализовано

- Текст и несколько файлов MD, DOCX, PDF, TXT до 30 МБ каждый; выбор, drag-and-drop, удаление и замена.
- Предварительная проверка расширения, размера, доступности чтения и отсутствия текста в MD/TXT. Проверка целостности DOCX/PDF и текстового слоя PDF должна выполняться сервисом анализа.
- Состояния подготовки, проверки файлов, обработки, завершения, ошибки и частичного результата.
- Независимое выделение, выделение всех доступных вопросов, снятие выделения, счётчик.
- Копирование нумерованного списка «вопрос + текущее понимание» в порядке таблицы. При отказе Clipboard API появляется поле ручного копирования.
- Новый анализ в отдельной вкладке, пустая форма для исправленной версии, запрет изменения материалов во время запуска.
- Текст результатов вставляется через `textContent`, а не исполняемый HTML; семантическая таблица, клавиатурный доступ, светлая и тёмная темы, мобильная компоновка.

## Граница интеграции

Сервис анализа в исходном проекте отсутствует. В текущем `dist/analysis.js` функция `analyzeDocument` сообщает о неподключённом сервисе и **не отправляет документы**. Отдельная кнопка «Посмотреть пример» открывает явно обозначенные демоданные из макета; пользовательские документы никогда не получают этот пример как результат анализа.

Для интеграции замените `analyzeDocument({ text, files, onProgress, onPartial })` в `dist/analysis.js` адаптером реального API и актуализируйте `serviceNotice`. Это локальная граница фронтенда, а не существующий HTTP-контракт. `onProgress(message)` обновляет описание обработки; `onPartial(result)` сохраняет доступные вопросы текущего запуска. Promise возвращает итоговый результат или отклоняется с `Error`. После ошибки ранее полученный частичный результат остаётся на экране.

Формат данных, ожидаемый представлением:

```js
{
  title: 'Название проекта',
  status: 'complete', // либо 'partial'
  summary: ['Первый абзац', 'Второй абзац'],
  questions: [{
    id: 'stable-question-id',
    text: 'Уточняющий вопрос?',
    subsystem: 'Подсистема',
    understanding: 'Текущее понимание',
    importance: 'Почему это важно'
  }],
  message: '' // пояснение частичного результата, если есть
}
```

`complete` требует 20 вопросов с уникальными ID и заполненными полями, а также 2–3 абзаца суммаризации. Неполные данные сохраняются и обозначаются как частичный результат; полностью непригодный ответ считается ошибкой. При новом запуске результат и выделение предыдущего запуска очищаются.

Серверное логирование запросов, файлов, результатов и отметок, распознавание документов и реальный AI-анализ не реализованы во фронтенде. Материалы не записываются в localStorage, IndexedDB или на диск. Вкладки не разделяют состояние. Локальный сервер отдаёт только перечисленные файлы приложения и не принимает загрузки.
