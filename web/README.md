# AI Solution Copilot — веб-интерфейс

Реализация варианта из [прототипа](../docs/design/copilot-mockups.html): адаптивная таблица, выбор отдельных вопросов и «Выделить все вопросы». [PNG интерфейса без запуска приложения](../docs/design/README.md).

## Запуск

Требуется Node.js 22 или новее. Зависимостей для установки нет.

```sh
cd web
npm start
```

Откройте http://127.0.0.1:4173. Другой порт: `PORT=4174 npm start`.

Локальный сервер также передаёт запросы `/api/start_process`,
`/api/get_progress/<id>` и `/api/get_questions/<id>` в Case Finder API,
снимая префикс `/api`. По умолчанию API ожидается на `http://127.0.0.1:8000`.
Другой адрес задаётся при запуске:

```sh
API_URL=http://127.0.0.1:8001 npm start
```

`API_URL` — HTTP(S) origin без пути, логина и пароля. Вход выполняется кнопкой
«Войти» в шапке: веб-сервер проверяет логин и пароль через `GET /whoami` и выдаёт
cookie `sid` (HttpOnly, SameSite=Strict). Пароль остаётся только в памяти процесса
веб-сервера и подставляется в запросы к API. Браузер пароль не хранит.
Для демопримера вход не нужен. В production используйте HTTPS.
Самостоятельная раздача `dist/` требует аналогичного proxy на `/api/`.

```sh
npm run check
npm test
```

Сквозная проверка с настоящими FastAPI и worker (только OpenAI и поиск кейсов
заменены существующими серверными тестовыми объектами):

```sh
# Из корня репозитория; используется lock-файл сервера.
uv sync --locked --project case-finder-main/server
cd web
CASE_FINDER_PYTHON="$PWD/../case-finder-main/server/.venv/bin/python" node --test tests/api-integration.mjs
```

Тест запускает loopback-серверы на свободных портах и сохраняет тестовые задания
в `.agent/api-integration/`. Реальные ключи OpenAI не используются.

Каталог `dist/` содержит готовую статическую страницу без этапа сборки. Его можно обслуживать любым HTTP-сервером. Открытие через `file://` не поддерживается из-за ES modules.

## Что реализовано

- Текст и несколько файлов MD, DOCX, PDF, TXT; выбор, drag-and-drop, удаление и замена. Сохранён клиентский предел 30 МБ на файл; сервер по умолчанию принимает до 10 файлов, 20 МБ на файл и 100 МБ суммарно. Ограничения сервера настраиваются в его `.env`; окончательную проверку выполняет API.
- Предварительная проверка расширения, размера, доступности чтения и отсутствия текста в MD/TXT. DOCX/PDF разбирает сервер, PDF без OCR.
- Состояния подготовки, проверки файлов, обработки, завершения, ошибки и частичного результата.
- Независимое выделение, выделение всех доступных вопросов, снятие выделения, счётчик.
- Копирование выбранных вопросов в порядке таблицы вместе с текущим пониманием и пояснением, почему вопрос важен. Подпись набора в текст не попадает. При отказе Clipboard API появляется поле ручного копирования.
- Для Case Finder вопросы двух наборов по 10 перемешиваются один раз на задание и показываются без метки набора. Кнопка «Подтвердить» фиксирует звёздочки; после этого выбор нельзя изменить.
- Новый анализ в отдельной вкладке, пустая форма для исправленной версии, запрет изменения материалов во время запуска.
- Текст результатов вставляется через `textContent`, а не исполняемый HTML; семантическая таблица, клавиатурный доступ, светлая и тёмная темы, мобильная компоновка.

## Подключение анализа

`dist/analysis.js:analyzeDocument` отправляет `multipart/form-data` на
`/api/start_process`: текст, оригинальные файлы, `question_count=10`,
`language=Russian`. Затем опрашивает `/api/get_progress/<id>` раз в две секунды
и получает `/api/get_questions/<id>?mode=both`. Авторизация идёт сессионной cookie.
Один HTTP-запрос ограничен двумя минутами; общая длительность задания не ограничена
браузерным таймером.

Сетевой сбой после получения ID позволяет продолжить получение того же задания
без повторной загрузки. ID, порядок вопросов, звёздочки и подтверждение хранятся
на веб-сервере в привязке к логину и восстанавливаются после перезагрузки страницы,
пока веб-сервер не перезапущен: пароль при перезапуске процесса нужно ввести снова.
Если связь оборвалась до получения ID, сервер мог принять задание; автоматического
повтора POST нет. Ошибки авторизации, документов, worker и сервера показываются
пользователю. Удаление файла из формы не удаляет серверные задания.

Ответ API преобразуется моделью `normalizeResult`:

```js
{ kind: 'case-finder', baseline: [{ question: 'Вопрос?', understanding: 'Что уже сказано.', importance: 'Почему это важно.' }], enriched: [] }
```

Каждый вопрос имеет ID с префиксом набора (`baseline-` или `enriched-`), но на экране
наборы перемешаны и подпись не показывается. Полным считается ответ с 10 объектами
в каждом наборе и непустыми `question`, `understanding`, `importance`. Строки без
пояснений сохраняются как частичный результат; полностью пустой ответ — ошибка.

Отдельная кнопка «Посмотреть пример» открывает явно обозначенные демоданные;
материалы при этом не отправляются. Демопример сохраняет прежний формат:

```js
{
  title: 'Название проекта',
  status: 'complete', // либо 'partial'
  summary: ['Первый абзац', 'Второй абзац'],
  questions: [{
    id: 'stable-question-id',
    text: 'Уточняющий вопрос?',
    subsystem: 'Подсистема',
    understanding: 'Текущее понимание',
    importance: 'Почему это важно'
  }],
  message: '' // пояснение частичного результата, если есть
}
```

Для этого формата `complete` требует 10 вопросов с уникальными ID и заполненными полями, а также 2–3 абзаца суммаризации. «Загрузить исправленное ТЗ» очищает сохранённое состояние аккаунта.

Оригиналы документов и результаты сохраняет Case Finder; текст передаётся в OpenAI.
Фронтенд не записывает материалы в localStorage, IndexedDB или на диск, вкладки
не разделяют состояние. Отметки вопросов и копирование веб-сервер сохраняет в SQLite
(см. ниже). Локальный веб-сервер отдаёт только перечисленные
файлы приложения; загрузки передаёт API без сохранения локальной копии.

Исходные требования: [ai_solution_copilot_web_interface.md](../materials/ai_solution_copilot_web_interface.md).

## Агентская фабрика

В форме доступен выбор между прежним Case Finder и новой фабрикой. Для сравнения
откройте два анализа и загрузите одинаковые `.md`. Старые форматы и два набора
вопросов сохранены для Case Finder. Фабрика принимает только `.md`, возвращает
переменное число замечаний (в том числе ноль), приоритеты, основания с оригинальными
строками, затронутые разделы и оценку проработанности компонентов.

`/api/factory/start_process`, `/api/factory/get_progress/<id>` и
`/api/factory/get_result/<id>` проксируются на `FACTORY_API_URL` (по умолчанию
`http://127.0.0.1:8002`), со снятием `/api/factory`. Способ анализа закреплён
за незавершённым заданием; повторное получение после сетевого сбоя не создаёт
новый запуск. Материалы и частичные результаты хранятся на сервере.

[Сборка, окружение, очередь и откат](../agent_factory_baseline/service/README.md).

## Журнал действий с вопросами

Клик по звёздочке, «Выделить все вопросы», «Снять выделение», копирование и «Подтвердить» отправляются на `POST /api/question_events`. Веб-сервер пишет их в SQLite: путь задаётся `QUESTION_EVENTS_DB`, в Compose это `/app/data/question-events.sqlite` на volume `web_data`. Перед записью сервер проверяет задание через `GET /get_progress/<id>` с авторизацией сессии. Если задание недоступно, действие не сохраняется. Демопример не записывается: у него нет идентификатора задания.

- `events` — журнал: кто, когда, какое действие (`star`, `unstar`, `select_all`, `clear`, `copy`, `copy_manual`, `confirm`) и тексты вопросов. В `confirm` поле `details.order` — порядок показа.
- `selections` — текущий набор отмеченных вопросов этого пользователя по заданию. При следующем открытии результата интерфейс восстанавливает звёздочки.
- `runs` — имена исходных файлов с экрана результата, чтобы связать отметки с документом.
- `sessions` — идентификатор cookie и логин. Пароль в базе не хранится.
- `user_state` — одно текущее задание на логин: способ анализа, `process_id`, порядок вопросов, тексты и время подтверждения.

`make export-labels` копирует SQLite и архив документов (`documents_archive`) в `exports/` и собирает JSONL подтверждённых разметок: документы, настоящий набор каждого вопроса, порядок показа и звёзды. Рядом пишется сводка долей отмеченных вопросов baseline и enriched.

Посмотреть отмеченные вопросы:

```sh
docker compose exec web sh -c 'apk add --no-cache sqlite && sqlite3 /app/data/question-events.sqlite "select r.source_names, s.username, s.question_text from selections s join runs r using (engine, process_id)"'
```

В образе `node:alpine` нет клиента `sqlite3`, поэтому команда ставит его на время вызова. Файл базы можно также открыть с хоста из каталога volume.
